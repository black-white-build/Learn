旧报告的评论请求全部使用不存在的视频 ID `1` 并返回 404，因此评论结果不能直接横向比较；旧混合流量的原始成功率也受这些 404 干扰。

## 5. 结论

1. 热门视频缓存优化在 50～100 并发下有效，QPS 和 P99 均有明显改善。
2. 视频列表虽提高了部分吞吐，但 P99 和失败率变差，暂不能认定列表缓存优化成功。
3. 并发达到 200 后多个接口的 P99 接近 10 秒超时线，当前线上较稳妥的持续并发仍建议控制在 50 左右。
4. 下一步应在服务器内部同时观察列表缓存命中率、Hikari pending、Tomcat busy threads、MySQL 慢查询和 Redis 延迟，再定位列表尾延迟来源。
5. 本轮之前曾启动过一次短暂测试并已中止，缓存预热和机器瞬时状态会带来误差；若用于简历数据，建议接入监控后冷却 5～10 分钟再重复 3 轮，采用中位数。

本报告中的“完成”仅表示场景执行完毕，不表示所有并发档位均达到性能目标。
